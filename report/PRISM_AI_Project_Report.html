Abstract

Enterprise resource planning systems accumulate operational data far faster than their users can interrogate it. A distribution business running such a system typically stores orders, invoices, expenses, inventory batches and channel-partner records across dozens of normalised tables, yet the people who most need answers from that data — owners, sales managers, warehouse supervisors — are rarely fluent in the reporting tools that expose it. The practical consequence is that routine questions such as “which products are running low?” or “who owes us money?” require either a pre-built report or a technically skilled intermediary.

This report documents the design, implementation and empirical evaluation of PRISM AI, a natural language interface built during an Artificial Intelligence internship and deployed inside a production CRM/ERP platform serving a personal-care products distributor. The system converts free-text business questions into structured queries against live operational data and returns computed answers, without transmitting any business data to an external service.

The work follows a deliberately hybrid design. A symbolic natural-language engine performs the operational path: text normalisation, stop-word removal, suffix stemming, synonym-to-concept expansion across 23 semantic groups, weighted intent classification over 17 intents, gazetteer-based named entity recognition, Damerau–Levenshtein fuzzy matching for typo tolerance, and dialogue state tracking for follow-up questions. In parallel, a statistical classifier was implemented entirely from first principles — a TF–IDF vectoriser over unigram and bigram features feeding a Multinomial Naive Bayes model with Laplace smoothing — and trained on a hand-constructed corpus of 659 labelled queries spanning the same 17 intents.

The classifier attains 85.8% accuracy on a stratified held-out test set of 169 queries and 78.7% (± 2.7%) accuracy under five-fold cross-validation, with a macro-averaged F1 score of 0.859. Against the 5.9% accuracy expected from uniform random assignment across 17 classes, the cross-validated result represents an improvement of approximately 13.3×. Reaching that figure required three distinct experimental iterations, documented in full. An initial implementation achieved only 45.9%; a cross-validated grid search over 180 hyperparameter configurations raised this to 54.6%; expanding the corpus lifted it to 75.8%; and a targeted correction of label ambiguity in the training data — identified through systematic error analysis rather than assumed — produced the final 85.8%.

A notable negative result is reported alongside the positive ones. Complement Naive Bayes, an algorithm specifically formulated for text classification with overlapping class vocabularies, was implemented and evaluated on the expectation that it would resolve the dominant confusion. It yielded an improvement of 0.4 percentage points, within run-to-run variance. This finding redirected effort from algorithm selection towards training-data quality, where the actual defect lay, and is retained in this report because the diagnostic reasoning it enabled was more valuable than the accuracy it failed to deliver.

Keywords: Natural Language Processing, Intent Classification, Named Entity Recognition, Naive Bayes, TF–IDF, Dialogue State Tracking, Approximate String Matching, Business Intelligence, Hybrid AI Systems.

Chapter 1: Introduction

Software that stores business data well does not necessarily make that data accessible. Over the past decade, small and mid-sized distribution businesses in India have adopted integrated CRM and ERP platforms at a rapid rate, digitising order books, ledgers and stock registers that were previously maintained on paper or in spreadsheets. The digitisation itself has largely succeeded. What has not kept pace is the interface through which non-technical staff retrieve information from these systems.

The dominant interaction model remains the dashboard: a fixed arrangement of charts and tables authored in advance by a developer. Dashboards serve recurring questions well, but they are structurally unable to serve the long tail of ad-hoc questions that characterise day-to-day operations. When a sales manager wants to know whether a particular distributor has slowed down, or a warehouse supervisor wants to know which items will exhaust before the next purchase order arrives, the dashboard either happens to contain that view or it does not. When it does not, the question is either abandoned or escalated to someone who can write a query.

Conversational interfaces offer a route around this constraint, and the emergence of large language models has made such interfaces broadly available. That availability, however, carries three costs that matter acutely in this setting. First, answering a question about business data using a hosted model requires transmitting that data to a third-party service, which is difficult to justify for financial records. Second, each query incurs both monetary cost and network latency. Third, and most seriously for a system of record, a generative model may produce a fluent and confident numerical answer that is simply incorrect.

The work reported here takes a different position. Rather than delegating comprehension to a hosted model, it constructs the comprehension layer directly: the system parses the question, identifies what is being asked, extracts which entities it concerns, and then computes the answer arithmetically from live records. Numbers are never generated — they are calculated. This design forgoes open-ended reasoning in exchange for determinism, zero marginal cost, complete data confidentiality and arithmetic correctness, a trade that is favourable for the class of questions an operational business actually asks.

1.1 Objectives of the Internship

The internship was structured around the following objectives:

  1. To study the classical natural-language understanding pipeline — normalisation, tokenisation, stemming, intent classification and entity recognition — and implement each stage without recourse to a pre-built NLP library.
  2. To design and construct a labelled training corpus adequate for supervised intent classification in a specific business domain, and to understand empirically how corpus size and corpus quality each affect model performance.
  3. To implement TF–IDF feature extraction and Naive Bayes classification from mathematical first principles, including Laplace smoothing and numerically stable posterior computation, in order to understand the algorithms rather than merely invoke them.
  4. To establish a rigorous evaluation methodology — stratified splitting, k-fold cross-validation, per-class precision/recall/F1, and confusion analysis — and to use it to drive development decisions rather than to justify them after the fact.
  5. To compare a symbolic, rule-driven approach against a statistical, learned approach on an identical task, and to characterise the conditions under which each is preferable.
  6. To integrate the resulting components into a production application such that the work is usable by real operators, not merely demonstrable in a notebook.

Chapter 2: Literature Review and Problem Statement

2.1 Domain Overview

Task-oriented dialogue systems — those built to accomplish a bounded set of user goals rather than to converse freely — are conventionally decomposed into three components: intent classification, which determines what the user wants; slot filling or named entity recognition, which determines the parameters of that request; and dialogue state tracking, which maintains context across conversational turns. This decomposition is the organising principle of commercial assistants and remains the standard reference architecture for goal-directed systems. The implementation reported here follows it directly, and the correspondence between the three classical components and the modules described in Chapter 3 is deliberate.

2.2 Review of Existing Approaches

2.2.1 Rule-based and symbolic systems

The earliest natural-language interfaces to databases were entirely symbolic, mapping surface forms to queries through hand-authored grammars and keyword rules. Such systems are wholly deterministic and completely auditable: for any output, the responsible rule can be identified. Their weakness is equally clear — coverage extends exactly as far as the rules an author has written, and every unanticipated phrasing constitutes a failure. They are, however, uniquely suited to situations where a wrong answer is more costly than no answer, and where the domain vocabulary is bounded.

2.2.2 Statistical text classification

Treating intent recognition as supervised text classification permits generalisation to phrasings absent from the training data. The standard representation is TF–IDF, which weights each term by its frequency within a document against its rarity across the corpus, thereby suppressing ubiquitous terms and elevating discriminative ones. Multinomial Naive Bayes remains a strong baseline for this representation despite its conditional-independence assumption being plainly violated by natural language; its efficiency and its stability on small corpora keep it in practical use. Rennie et al. (2003) identified systematic weaknesses in the multinomial formulation when class sizes or vocabularies are uneven, and proposed Complement Naive Bayes, which estimates each class's parameters from the complement of that class. This variant was implemented and evaluated as part of the present work; the outcome is reported in Section 4.4.

2.2.3 Neural and transformer-based approaches

Contemporary state-of-the-art intent classification uses contextual embeddings from pre-trained transformer encoders, which capture word order and semantic similarity in a manner bag-of-words representations cannot. The accuracy advantage is substantial. The costs, however, are a model of tens or hundreds of megabytes, inference latency, and a training requirement well beyond what could be satisfied by a corpus constructed by one intern over an internship period. For a component that must execute within a browser and return an answer instantaneously, these costs were judged prohibitive at the present scale, though the limitation this imposes is acknowledged directly in Section 5.2.

2.2.4 Large language models as a comprehension layer

Delegating comprehension to a hosted generative model — supplying business records as prompt context and requesting an answer — is the lowest-effort route to broad coverage, and was the approach taken by the initial version of the assistant this project replaced. Evaluation of that version surfaced four objections. Every query transmitted order, invoice and expense records to a third-party endpoint. Each query cost money and took between one and three seconds. Availability depended on network connectivity and on the provider's uptime. Most consequentially, the model occasionally produced numerically incorrect figures stated with complete confidence — an acceptable failure mode for a drafting tool and an unacceptable one for a system of record.

2.3 Problem Statement

The problem addressed by this work may be stated as follows:

Given a free-text business question posed by a non-technical operator, determine the operator's intent and the entities the question concerns, and return a numerically correct answer computed from live operational data — subject to the constraints that no business data may leave the client environment, that the response must be effectively instantaneous, that the system must incur no per-query cost, and that reported figures must be computed rather than generated.

Four subsidiary requirements follow from deployment in a real workplace. The system must tolerate misspelling, since operators type quickly on mobile devices. It must support follow-up questions, since a question such as “and last month?” is meaningless in isolation but natural in sequence. It must decline explicitly when a question falls outside its competence, rather than guessing. And it must expose its reasoning, so that a user can judge whether an answer addressed the question actually asked.

2.4 Rationale for a Hybrid Architecture

The rule-based and statistical approaches fail in complementary directions. A rule system fails on unanticipated phrasing but never fails silently: the intent is either matched or it is not, and the decision is inspectable. A statistical classifier generalises to novel phrasing but offers no comparable guarantee, and — as Section 4.5 shows — inherits any inconsistency present in its training labels.

The architecture adopted here retains both. The symbolic engine serves the operational path, because it additionally performs entity extraction and dialogue state tracking, which the classifier does not attempt. The statistical classifier is trained, evaluated and exposed alongside it, providing a quantified measure of how far a learned model reaches on the same task and, through disagreement between the two, a diagnostic signal indicating where the rule vocabulary is incomplete.

3.2 Linguistic Preprocessing

Raw input passes through four transformations before any classification occurs.

Normalisation lowercases the input and removes punctuation, while preserving the currency symbol, the percent sign, the decimal point and the hyphen, each of which carries meaning in this domain. Whitespace is collapsed.

Tokenisation splits on whitespace, followed by removal of a stop-word list covering determiners, auxiliaries, pronouns and conversational filler. The list was tuned by inspection: interrogatives such as how, which and who are deliberately retained, since they are among the strongest available signals for distinguishing a count request from a value request.

Stemming applies suffix stripping so that morphological variants collapse to a shared root — invoices, invoicing and invoiced all reduce to a common form. A rule-based stripper was chosen over a full Porter implementation because the domain vocabulary is bounded and the additional precision of a complete algorithm was not measurable against the added complexity.

Concept expansion maps each surviving token to a canonical concept through a synonym dictionary of 23 semantic groups. This stage is what allows turnover, sales, topline and billing to be recognised as expressions of a single underlying idea, and it is the principal mechanism by which the symbolic engine achieves coverage without an example of every phrasing.

3.3 Intent Classification — Symbolic Path

Each of the 17 intents is defined by a set of required concepts, a set of supporting concepts and a set of negative concepts. An intent scores by accumulating weight for each required and supporting concept present in the input, and is disqualified outright if a negative concept appears. The highest-scoring intent above a confidence floor is selected; if no intent clears the floor, the system returns an explicit statement of non-comprehension rather than its best guess. 3.4 Named Entity Recognition

Entity recognition is performed by gazetteer matching against the live database rather than against a static list. Product names are drawn from the current catalogue, personnel names from the user table, customer and distributor names from the partner tables, and state names from the territory configuration. A consequence of this design worth noting is that the recogniser requires no retraining when the business adds a product or onboards a distributor — the new entity becomes recognisable the moment it is persisted.

Two further entity classes are extracted by pattern rather than by gazetteer: fulfilment and pipeline statuses, matched against their controlled vocabularies, and temporal expressions such as today, last week or this quarter, which are resolved into concrete date ranges.

3.5 Approximate String Matching

Operators type quickly and misspell often, and an interface that fails on a single transposed character is of limited practical use. Tolerance is provided by the Damerau–Levenshtein edit distance, which extends the standard Levenshtein formulation with an adjacent-transposition operation.

The choice of Damerau over plain Levenshtein was empirically motivated. Transposition is among the most frequent categories of keyboard error, and the standard formulation charges two edits for a single transposed pair: unpiad → unpaid is distance 2 under Levenshtein but distance 1 under Damerau. Since a tight edit budget is required to control false positives, this single-unit difference determines whether the most common real-world typo is corrected at all.

The implementation terminates early: if every cell in a row of the dynamic-programming matrix already exceeds the permitted budget, no completion can fall within it, and the computation is abandoned. This bounds the cost of comparing a token against the full vocabulary.

3.6 Dialogue State Tracking

Questions in sequence depend on their predecessors. “And last month?” carries no independent meaning; it inherits both the subject and the metric of the question preceding it. The system maintains, after each successfully answered turn, the resolved intent together with the entities that participated in it.

A subsequent turn is classified as a continuation when any of three conditions holds: it opens with a continuation marker (what about, how about, and, same for); it contains a referential expression (it, them, their, that) without an independently resolvable intent; or it names a concrete entity while matching no intent of its own. On continuation, the prior intent is inherited and entities are merged, with newly supplied entities overriding their remembered counterparts and unmentioned ones persisting. The following exchange illustrates the mechanism:

User  : revenue by state
PRISM : Gujarat  Rs 95,000 (76%)  |  Maharashtra  Rs 30,000 (24%)

User  : what about Gujarat?          [continuation marker -> intent inherited]
PRISM : Gujarat — Rs 95,000, 2 orders, 76% of national sales

User  : and last 30 days?            [continuation -> entity {state} retained,
PRISM : Gujarat — Rs 50,000, 1 order  entity {timeframe} newly supplied]

3.7 Predictive Analytics Module

A separate analytics surface derives forward-looking indicators from the same operational data. It is important to characterise these methods accurately: they are statistical heuristics, not machine learning. No parameters are fitted and no model is trained. Demand projection uses a three-month moving average per product with a trend adjustment; depletion forecasting divides available stock by observed daily consumption velocity; disengagement scoring combines order recency with a decline term; dead-stock detection flags catalogue items with no movement over a fixed window; and opportunity prioritisation applies a weighted sum over pipeline stage, deal value and recency. These techniques are appropriate to the data volumes available and are transparent to the operator, but they are reported here as descriptive analytics rather than as learned models.

3.8 Statistical Classifier — Implementation

The machine-learning subsystem was implemented without any external library, so that each mathematical step could be examined directly.

3.8.1 Corpus construction

A corpus of 659 labelled queries was authored by hand across the 17 intents, with between 30 and 55 examples per class. Phrasings were varied deliberately along four dimensions — length, register, word order and lexical choice — so that the model would learn discriminative terms rather than memorise sentence templates. Indian-English business vocabulary (godown, party, offtake, lakh) was included because it reflects the register in which the system's users actually speak.

3.8.2 Feature extraction

Features comprise unigrams and bigrams over the preprocessed token stream. Bigrams were included because short business queries hinge on word pairs that unigrams cannot separate: how many requests a count while how much requests a value, and the two differ in exactly one token. Bigrams occurring in fewer than three documents are discarded, as a bigram appearing once encodes a specific training sentence rather than a generalisable pattern.

Term weights follow the smoothed TF–IDF formulation

idf(t) = ln[ (1 + n) / (1 + df(t)) ] + 1

where n is the document count and df(t) the document frequency of term t. Vectors are subsequently L2-normalised so that query length does not influence classification.

3.8.3 Multinomial Naive Bayes

Class-conditional feature likelihoods are estimated with Lidstone smoothing:

P(t | c) = ( Σd∈c w(t,d) + α ) / ( Σt' Σd∈c w(t',d) + α·|V| )

with α = 0.3 and |V| the vocabulary size. Smoothing is not optional here: an unsmoothed estimate assigns zero probability to any term unobserved in a class, and since scores are accumulated in log space, a single such term would collapse the entire posterior to negative infinity. Classification maximises the log posterior

ĉ = argmaxc [ ln P(c) + Σt w(t) · ln P(t | c) ]

and posteriors are recovered by a softmax with the maximum score subtracted before exponentiation, which prevents overflow.

3.8.4 Complement Naive Bayes

Complement Naive Bayes was additionally implemented for comparison. Rather than estimating each class's parameters from its own documents, CNB estimates them from every document not in the class and selects the class whose complement fits least well. The formulation includes a weight-normalisation step which prevents classes with larger vocabularies from dominating. The motivating hypothesis was that CNB would resolve the dominant confusion identified in error analysis; Section 4.4 reports the outcome.

3.8.5 Evaluation methodology

Evaluation follows four principles adopted at the outset and held to throughout.

Stratified splitting. The corpus is divided 75:25 with class proportions preserved, guaranteeing that every intent is represented in both partitions.

Determinism. All shuffling derives from a seeded pseudo-random generator, so that any reported figure can be reproduced exactly.

Cross-validation. Five-fold cross-validation is reported alongside the single-split figure. On a corpus of this size a single split is materially affected by which examples happen to fall into the test partition, and the cross-validated mean is treated as the honest estimate throughout this report.

Per-class reporting. Aggregate accuracy can mask systematic failure on individual classes. Precision, recall and F1 are therefore reported per intent, together with the full confusion matrix, and it was inspection of that matrix — not the aggregate figure — that identified the defect resolved in Section 4.5.

Three observations follow from Table 4.3.

Six intents achieve F1 at or above 0.90. These are classes possessing distinctive vocabulary with little overlap elsewhere in the corpus — dead_stock owns unsold, stagnant and obsolete; forecast owns predict, projection and demand.

The help intent exhibits high precision (0.90) with markedly lower recall (0.69). The improvement of 0.4 percentage points falls well within the 2.7-point standard deviation across folds and cannot be distinguished from noise. Furthermore, CNB's weight-normalisation step compressed the posterior distribution so severely that reported confidence collapsed to approximately 6% — technically a correct argmax, but useless as a value displayed to a user.

This result is retained in the report because its diagnostic value exceeded its accuracy value. The hypothesis under test was that the deficiency lay in the algorithm. The measurement refuted that hypothesis, and in doing so redirected effort towards the training data, where the defect actually resided. Had CNB been adopted on the strength of its theoretical suitability without measurement, the underlying labelling problem would have persisted undetected.

4.5 Error Analysis and Corpus Disambiguation

Inspection of the confusion matrix after iteration 3 revealed that errors were not uniformly distributed. A single ordered pair — true profit predicted as revenue_total — accounted for four of the 31 test errors, approximately 14% of the total. No other pair exceeded two.

Examination of the training examples for both classes exposed the cause:

Labelled revenue_total : "how much money did we make from sales"
Labelled revenue_total : "total earnings from orders"
Labelled revenue_total : "what did we earn last week"

Labelled profit        : "how much profit did we make"
Labelled profit        : "what is our earning after costs"
Labelled profit        : "net earnings figure"

The terms earn, money and make appeared with comparable frequency under both labels. The model had learned exactly what the corpus taught it — that these terms are uninformative — and the failure was therefore an artefact of the training data, not a limitation of the classifier.

The remedy restructured the lexical territory of the two classes. revenue_total was re-anchored on unambiguous turnover vocabulary (turnover, topline, sales value, billing), and the ambiguous earning-related phrasings were reassigned to profit, where they were reinforced with additional examples. A second, smaller leak was found and corrected in the same pass: a churn example phrased “which partners have low activity” was drawing the term low towards low_stock.

The final point merits emphasis, as it constitutes a methodological caution. Evaluating the rule engine against a corpus written with knowledge of its vocabulary would produce an inflated figure measuring self-consistency rather than generalisation. The two systems are therefore compared qualitatively on capability, and only the classifier — which was evaluated against data held out from its own training — is assigned a numerical accuracy.

Both are exposed simultaneously in the application's evaluation dashboard, where a user may enter any query and observe both verdicts. Disagreement between them is surfaced explicitly, and in practice indicates one of two conditions: a phrasing the rule vocabulary does not yet cover, or a query the classifier has assigned on weak evidence.

4.8 Key Takeaways

  1. Data quality dominated algorithm selection. Corpus work delivered 24.1 points of improvement across iterations 3 and 4; the algorithmic substitution delivered 0.4 points, within noise.
  2. Aggregate accuracy conceals structure. The defect resolved in Section 4.5 was invisible in the aggregate figure and apparent only in the confusion matrix. Per-class reporting was not a presentational nicety but the instrument that located the fault.
  3. A negative result can be more informative than a positive one. The CNB experiment failed to improve accuracy but succeeded in refuting a hypothesis, which is what redirected effort productively.
  4. Calibration is a distinct concern from accuracy. A configuration may maximise correctness while rendering its confidence output meaningless. Where confidence is displayed, it must be treated as part of the deliverable.
  5. Cross-validation is essential at this scale. The single-split figure exceeded the cross-validated mean by 7.1 points; reporting only the former would have overstated the system's capability.

Chapter 5: Conclusion and Recommendations

5.1 Conclusion

This internship produced a working natural-language interface to a production enterprise system, together with a rigorously evaluated statistical classifier for the same task. The symbolic engine implements the three canonical components of a task-oriented dialogue system — intent classification, named entity recognition and dialogue state tracking — with Damerau–Levenshtein approximate matching providing tolerance to the misspellings that characterise real operator input. The statistical classifier, implemented from mathematical first principles without recourse to any machine-learning library, achieves 85.8% accuracy on held-out data and 78.7% (± 2.7%) under five-fold cross-validation across 17 intent classes, approximately 13.3 times the random baseline.

The system satisfies the constraints set out in Section 2.3. No business data leaves the client environment. Responses are computed rather than generated, so a numerical answer is either correct or absent — never plausibly wrong. Marginal cost per query is zero and inference is instantaneous. The system declines explicitly when a question falls outside its competence.

The more durable outcome, however, is methodological. The accuracy progression from 47.1% to 78.7% was not achieved by trying successive algorithms until one performed better. Each iteration was preceded by a diagnostic step that identified what was actually failing: overfitting was diagnosed from the divergence between training and test accuracy; near-uniform posteriors were traced to normalisation compressing the score range; and the dominant confusion pair was root-caused to inconsistent labelling in data authored by hand. The intervention that produced the largest gain was corpus expansion, and the intervention that failed was the algorithmic substitution undertaken on the strongest theoretical grounds. Measuring before changing, and retaining the result when the measurement contradicted the expectation, is the principal transferable lesson of the work.

5.2 Limitations

Four limitations are acknowledged.

Representational ceiling. A bag-of-words model with bigrams encodes no word order beyond adjacent pairs. Queries whose meaning depends on longer-range structure cannot be resolved reliably, and this bounds achievable accuracy irrespective of further corpus growth.

Corpus scale and provenance. At 659 examples the corpus remains small, and the persistent gap between training accuracy (98.8%) and cross-validated accuracy (78.7%) indicates residual overfitting. The corpus was moreover authored by a single individual, and therefore reflects one person's expectations about phrasing rather than an observed distribution of real user queries.

Bounded competence. The system answers within 17 defined intents and cannot perform open-ended reasoning, multi-step analysis or hypothetical inference. This is a deliberate consequence of the architecture, not a defect, but it is a real constraint on applicability.

Heuristic analytics. The predictive module employs statistical heuristics rather than fitted models, as stated in Section 3.7. Its outputs are descriptive extrapolations and should not be interpreted as learned forecasts.

5.3 Recommendations for Future Work

  1. Collect real query logs. The single highest-value next step is to instrument the deployed system and accumulate genuine user queries with their resolved intents. This would replace an author's expectations with an observed distribution and would supply training data at a scale hand-authoring cannot reach.
  2. Introduce sentence embeddings. A compact sentence-transformer producing dense semantic representations would overcome the bag-of-words ceiling by recognising semantic similarity between queries sharing no vocabulary. A quantised model is feasible in-browser, and this is the most direct path past approximately 85% accuracy.
  3. Calibrate reported confidence. Naive Bayes posteriors are known to be poorly calibrated. Applying Platt scaling or isotonic regression on a validation partition would align the displayed confidence with observed correctness, permitting a principled abstention threshold.
  4. Extend intent coverage. Procurement, scheme and claim management, complaint handling and field-force attendance are represented in the underlying platform but are not yet addressed by the language interface.
  5. Add genuine unsupervised learning. K-means clustering over RFM features would provide data-driven customer segmentation, complementing the present supervised classification with an unsupervised technique on the same operational data.
  6. Employ the classifier in the operational path. At present the classifier is evaluated and displayed but does not serve live queries. A hybrid arrangement — classifier for intent, symbolic engine for entities and dialogue state — would combine the generalisation of the former with the precision of the latter.

A.1 Damerau–Levenshtein Distance with Early Termination

const editDistance = (a, b, max = 2) => {
  if (a === b) return 0;
  if (Math.abs(a.length - b.length) > max) return max + 1;
  let prev2 = null;
  let prev = Array.from({ length: b.length + 1 }, (_, i) => i);
  for (let i = 1; i <= a.length; i++) {
    const cur = [i];
    let rowBest = i;
    for (let j = 1; j <= b.length; j++) {
      const cost = a[i - 1] === b[j - 1] ? 0 : 1;
      let d = Math.min(prev[j] + 1, cur[j - 1] + 1, prev[j - 1] + cost);
      if (i > 1 && j > 1 && a[i - 1] === b[j - 2] && a[i - 2] === b[j - 1]) {
        d = Math.min(d, prev2[j - 2] + 1);       // adjacent transposition
      }
      cur[j] = d;
      if (d < rowBest) rowBest = d;
    }
    if (rowBest > max) return max + 1;           // whole row exceeds budget
    prev2 = prev;
    prev = cur;
  }
  return prev[b.length];
};

A.2 Multinomial Naive Bayes — Parameter Estimation

fit(vectors, labels, nFeatures) {
  this.classes = [...new Set(labels)].sort();
  const classIdx = new Map(this.classes.map((c, i) => [c, i]));
  const counts = new Array(this.classes.length).fill(0);
  const featureSum = this.classes.map(() => new Float64Array(nFeatures));

  vectors.forEach((vec, i) => {
    const ci = classIdx.get(labels[i]);
    counts[ci]++;
    vec.forEach((w, fi) => { featureSum[ci][fi] += w; });
  });

  this.logPrior = counts.map(c => Math.log(c / labels.length));

  this.logLikelihood = featureSum.map(row => {
    let total = 0;
    for (let i = 0; i < nFeatures; i++) total += row[i];
    const denom = total + this.alpha * nFeatures;    // Lidstone smoothing
    const out = new Float64Array(nFeatures);
    for (let i = 0; i < nFeatures; i++)
      out[i] = Math.log((row[i] + this.alpha) / denom);
    return out;
  });
  return this;
}

A.3 Numerically Stable Posterior Computation

predictProba(vec) {
  const scores = this.decisionFunction(vec);
  const max = Math.max(...scores);
  const exp = scores.map(s => Math.exp(s - max));   // shift prevents overflow
  const sum = exp.reduce((a, b) => a + b, 0);
  return exp.map(e => e / sum);
}
